# Listo · אפליקציית הקהילה (גרסה 0.1)

קהילת תיווך שיתופי למתווכים מורשים. הגרסה כוללת:

- כניסה עם קוד חד־פעמי במייל.
- פרופיל מתווך עם מספר רישיון, ואימות ידני של הרישיון.
- מאגר נכסים, לוח מבוקשים והתאמה אוטומטית עם התראות.
- בקשת שיתוף פעולה: הצעת חלוקה או הצעה נגדית, והסכם שנחתם דיגיטלית. פרטי המוכר נחשפים רק אחרי ששני הצדדים חתמו.
- דיווח על עסקה ואימות שלה בידי הצד השני.
- מסך ניהול.

## העקרונות שבנויים בתוך מסד הנתונים

- **Listo לא קובעת חלוקה.** המתווך המפרסם מציע, המתווך של הקונה מקבל או מציע הצעה נגדית. אין חלוקה ברירת מחדל ואין עמלה מינימלית.
- **פרטי המוכר והכתובת המלאה** נשמרים בטבלה נפרדת (`listing_private`). רק המתווך המפרסם, והמתווך שחתם איתו על שיתוף פעולה, יכולים לקרוא אותה.
- **רק מתווכים מאומתים** רואים את המאגר ואת לוח המבוקשים. מתווך לא יכול לאמת את עצמו.
- **שיתופי פעולה ועסקאות** נוצרים רק דרך פונקציות במסד הנתונים, שבודקות כל כלל: הזמנת תיווך חתומה, אי אפשר לבקש שת״פ על נכס של עצמך, רק המתווך המפרסם חותם בצד שלו, ומי שדיווח על עסקה לא יכול לאמת אותה בעצמו.

## הטכנולוגיה

- Next.js 14 עם TypeScript ו־Tailwind, בעברית ומימין לשמאל. אפשר להוסיף את האתר למסך הבית בטלפון.
- Supabase: מסד נתונים Postgres עם הרשאות לפי שורה (RLS), התחברות, ואחסון תמונות.
- Vercel להעלאה לאוויר.

## הקמה, צעד אחר צעד

### 1. Supabase

1. פותחים פרויקט חדש ב־[supabase.com](https://supabase.com), באזור Frankfurt. זה האזור הקרוב לישראל.
2. נכנסים ל־**SQL Editor**, ומריצים לפי הסדר:
   - `supabase/migrations/20261116000000_init.sql`
   - `supabase/migrations/20261116000100_storage.sql`
3. ב־**Authentication → Providers → Email**:
   - משאירים את Email מופעל.
   - מבטלים את Confirm email. הקוד עצמו מאמת את הכתובת.
4. ב־**Authentication → Email Templates → Magic Link** מחליפים את גוף ההודעה כך שיכלול את הקוד:
   ```html
   <h2>הקוד שלך ל־Listo</h2>
   <p style="font-size:28px;letter-spacing:6px"><b>{{ .Token }}</b></p>
   <p>הקוד בתוקף לשעה. אם לא ביקשת להיכנס, אפשר להתעלם מההודעה.</p>
   ```
5. ב־**Authentication → URL Configuration** מגדירים את Site URL לכתובת האתר, למשל `https://golisto.co.il`.
6. בשביל שליחת מיילים אמיתית, ולא רק כמה מיילים לבדיקה, מחברים ספק SMTP ב־**Project Settings → Auth → SMTP**. אפשר למשל Resend או Brevo, ולשניהם יש מסלול חינמי.

### 2. להפוך את עצמכם למנהלים

נכנסים פעם אחת לאתר, ממלאים את הפרופיל, ואז מריצים ב־SQL Editor:

```sql
update public.profiles set is_admin = true, status = 'verified' where email = 'המייל-שלכם@example.com';
```

### 3. הרצה מקומית

```bash
npm install
cp .env.example .env.local   # ממלאים את הכתובת והמפתח מ־Project Settings → API
npm run dev                  # http://localhost:3000
```

#### קוד כניסה קבוע בזמן פיתוח

כדי לא לחכות למייל בכל כניסה במחשב שלכם, מוסיפים ל־`.env.local`:

```bash
DEV_LOGIN_CODE=123456
DEV_LOGIN_PASSWORD=מחרוזת-אקראית-ארוכה-לפחות-16-תווים
```

נכנסים פעם אחת עם הקוד מהמייל. מאותו רגע, כש־`npm run dev` רץ, אפשר ללחוץ במסך הכניסה על "מצב פיתוח" ולהקליד 123456.
הקוד הקבוע עובד רק במצב פיתוח. לא מגדירים את שני המשתנים האלה ב־Vercel.

### 4. העלאה לאוויר ב־Vercel

1. מעלים את הקוד ל־GitHub.
2. ב־[vercel.com](https://vercel.com) בוחרים **Add New → Project** ומייבאים את המאגר.
3. מוסיפים את שלושת משתני הסביבה מ־`.env.example`.
4. מחברים את הדומיין ב־**Settings → Domains**.

### 5. משימה יומית: תפוגת הפניות

הפניה חתומה בתוקף 120 יום. כדי לסמן הפניות שפג תוקפן, מפעילים ב־Supabase את התוסף `pg_cron` (Database → Extensions), ומריצים:

```sql
select cron.schedule('expire-coops', '0 3 * * *', $$ select public.expire_coops(); $$);
```

## מה עוד לא בפנים

- העורך האוטומטי לסרטונים וערכת ההשקה. בינתיים מעלים תמונות או קישור לסרטון.
- דף נכס ציבורי עם QR ולידים, ודוח שבועי למוכר.
- ערוץ קבלנים, סולם שגרירים, מנויים וסליקה.
- התראות בוואטסאפ. כרגע ההתראות מופיעות רק בתוך האתר.
- עריכת נכס קיים. כרגע אפשר רק לשנות סטטוס.
- נוסח ההסכם (`agreement_versions`) הוא טיוטה לדוגמה, וחייב לעבור עורך דין לפני שימוש אמיתי.
